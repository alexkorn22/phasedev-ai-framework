# Карточка скилла: `<name>`

Шаблон рабочей карточки дистилляции. Одна карточка на скилл, файл `docs/skill-distillation/cards/<name>.md`. Карточка ведётся с шага 1 конвейера и закрывается приёмкой; сам скилл живёт в `skills/<name>/SKILL.md`.

## Паспорт

- **Скилл**: `<name>` (kebab-case; суффикс `-method` для методных скиллов)
- **Волна**: N
- **Роли-потребители**: `<роль1>, <роль2>` (из целевого каталога §5.3 роадмапа)
- **Статус**: inventory | extracted | filtered | assembled | accepted-L1 | accepted-L2 | cancelled

## Шаг 2. Экстракт

Ссылка на файл экстракта или сам экстракт: каждое нормативное утверждение с меткой `файл:строка`. На этом шаге ничего не отбрасывается и не переформулируется.

## Шаг 3. Решения фильтров

Порядок обязателен: 1 → 2 → 3, каждый следующий работает по выходу предыдущего.

| # утверждения | Фильтр 1 (lifecycle) | Фильтр 2 (дельта к своду) | Фильтр 3 (поведенческая дельта) | Итог |
|---|---|---|---|---|

- Фильтр 1 режет: чужие агенты/скиллы/команды, скрипты, провайдеры, MCP, хуки, session/checkpoint-механику, git/PR-ритуалы, форматы отчётов и артефактов, boilerplate.
- Фильтр 2: выживает только то, чего действующая библиотека (включая `dev-core`) ещё не несёт. Более строгая формулировка донора = заявка на усиление существующего скилла через конфликт-лог, не дубль.
- Фильтр 3: выживает только то, без чего модель повела бы себя иначе.

## Шаг 4. Конфликты

Ссылки на записи `conflict-log.md`, затронутые этим скиллом. Новая запись фиксируется ДО сборки скилла.

## Шаг 5. Сборка — правила формы (§7 роадмапа)

Скелет `skills/<name>/SKILL.md` (контент — английский):

```markdown
---
name: <name>
description: Use when <условие применения — конкретное, наблюдаемое>
version: 1.0.0
compatibility: universal
metadata:
  source: distilled
---

# <Title>

## Purpose
## When to Use
## <Method / Algorithm>
## <Checklist / Thresholds>
## Red Flags
## Completion Condition
```

Чеклист формы:

- [ ] Объём: 1–2 страницы, ориентир ≤150 строк SKILL.md; не влезло → `references/` или это не прошло фильтр 3.
- [ ] Ноль знаний о PhaseDev: никаких фаз, артефактов, вердиктов, `state.json`, findings-команд.
- [ ] Ноль знаний о доноре: никаких ссылок на донорские библиотеки, их агентов, скиллы, команды.
- [ ] Никаких форматов вывода: метод и критерии, не структура отчёта.
- [ ] Формулировки-победители перенесены дословно (MIT), не пересказаны.
- [ ] Стековые дельты — только в `skills/<name>/references/<lang>.md`, 100–150 строк на язык.

## Шаг 6. Приёмка

**Уровень 1 — статическая** (обязателен до коммита):

- [ ] Объём в лимите.
- [ ] Grep не находит: `PhaseDev`, `phasedev`, названий фаз, `verdict`, `state.json`, имён артефактов.
- [ ] Grep не находит имён донорских агентов/скиллов, слэш-команд и путей к скриптам донора.
- [ ] Нет секций, задающих формат отчёта или артефакта.
- [ ] Каждое правило проходит фильтр 2 (аналога в библиотеке нет).
- [ ] Каждое правило проходит фильтр 3 (видно, какое поведение меняет).
- [ ] Фронтматтер полный, `description` в формате «Use when …».

**Уровень 2 — поведенческая** (батчем после волны): прогон реальной фазы дважды — роль без скилла и со скиллом. Разница не наблюдаема или не объяснима правилами скилла → скилл отменяется, не дорабатывается.

## Интеграция (§11, в том же коммите, что и скилл)

- [ ] Скилл прописан в `roles` (`config.yaml`) у ролей-потребителей.
- [ ] Таблица ролей в `README.md` обновлена.
- [ ] `bun test` + `npm run typecheck` зелёные.
- [ ] Смоук `phasedev spawn-plan --harness claude-code` печатает роль с новым списком.
