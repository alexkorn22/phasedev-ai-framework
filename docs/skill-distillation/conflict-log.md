# Конфликт-лог дистилляции

Правило: где донор противоречит действующему своду — по умолчанию побеждает действующий свод. Каждая новая запись фиксируется ДО сборки скилла, чтобы конфликт не переоткрывался на каждом следующем скилле.

Стартовые записи перенесены из §8 роадмапа (`skill-distillation-roadmap.md`, ревизия 3, 2026-08-04).

| # | Тема | Позиция донора | Позиция нашего свода | Решение | Адрес (скилл) |
|---|---|---|---|---|---|
| 1 | Порог покрытия тестами | Вторичный донор: «минимум 80% покрытия, все три типа тестов обязательны» | Тест оправдан, только если может упасть по реальной поведенческой причине | Побеждает наш свод. Порог покрытия — приглашение писать балласт. Кусок не переносится | — (отказ) |
| 2 | Размер функции/файла | Оба донора: числовые пороги по типам файлов | Качественные триггеры (вложенность, число параметров, смешение уровней) | Числовые пороги берём как **вспомогательный сигнал ревьюера** (нужен воспроизводимый порог), не как правило написания кода | `code-review-method` |
| 3 | Вердикты и пороги | Основной донор: CQ PASS ≥86% / CONDITIONAL ≥79% / FAIL; Q PASS/FIX/REWRITE | `verdict`, `blockingSeverity` и маршрутизация принадлежат фреймворку | Берём гейты как **чеклист** и стандарты доказательности. Машинку порогов и вердиктов не берём | `code-review-method`, `test-quality-method` |
| 4 | Шкала важности | Основной донор: канонические S1–S4 с маппингом на семь словарей | MUST-FIX / RECOMMENDED / NIT | Вторую шкалу не заводим. Берём **модель уверенности** (0–25 отбросить, 26–50 не сообщать, 51+ сообщать) как фильтр перед репортом находки | `code-review-method` |
| 5 | Остановки в потоке | Основной донор: не спрашивать пользователя; автономная диспозиция разрешает агенту самому править спеку | Approval gates и `autoApprove` — замороженный контракт фреймворка | Берём только запрет **псевдо-пауз внутри одной фазы** («сделал 3 из 12, продолжать?»). Автономную правку спеки и обход гейтов — нет | ⚠ не назначен (см. примечание) |
| 6 | Тотальность TDD | Основной донор: «нет продакшн-кода без падающего теста», исключения только для конфигов, доков и чистого рефактора | Test Economy (`dev-core`): не писать тест, который ничего не тестирует | **Решено пользователем 2026-08-04:** берём только механику цикла, тотальность — нет. Test Economy владеет «что покрывать», донор — «как писать тест, когда решено покрывать». Механика живёт в отдельном скилле | `tdd-method` |
| 7 | Формат спеки | Вторичный донор: разметка OpenSpec с HTML-метаданными | Формат spec-артефактов принадлежит фреймворку | Берём метод извлечения поведения, отбрасываем разметку целиком | `spec-delta-method` |
| 8 | Документация изменений | Основной донор: каждый прогон, приземливший код, трогает CHANGELOG | Документация идёт через `spec_sync` на фазе архива | Не берём — механизм уже есть и живёт в другом месте флоу | — (отказ) |

## Примечания

- **№5, адрес принятой части.** Запрет псевдо-пауз принят, но ни один скилл §5.1 его не несёт — тот же тихий шаблон отказа, что был найден на TDD (решение есть, адреса нет). Кандидаты: `verification-method` (Red Flags: пауза-отчёт как суррогат завершения) или `tdd-method` (дисциплина исполнителя). Назначить при сборке первого из них; не потерять.
