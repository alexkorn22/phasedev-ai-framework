## Цель

С нуля создать рабочий HTTP-сервис сокращения ссылок в новом репозитории.

## Стек (закрыто)

- Язык: TypeScript
- Рантайм: Bun
- База: SQLite
- HTTP: встроенный сервер Bun (`Bun.serve`), без веб-фреймворка
- SQLite: встроенный драйвер Bun (`bun:sqlite`)
- Тесты: `bun:test`, команда `bun test`
- Новые npm/bun-зависимости запрещены
- Файл базы: `data/app.sqlite` (каталог `data/` создаётся при старте, если его нет)
- Порт: переменная окружения `PORT`, по умолчанию `3000`
- Слушать все интерфейсы на этом порту
- Стек не обсуждать и не заменять

## Контракт HTTP

Тела запросов и ответов — UTF-8 JSON. Лишний неизвестный путь: `404` и `{"error":"not_found"}`. Известный путь, неверный метод: `405` и `{"error":"method_not_allowed"}`.

### `POST /links`

Создать сокращение.

Запрос:

- `Content-Type: application/json`
- тело: `{"url":"<строка>"}`
- прочие поля тела игнорировать

Успех: `201`, `Content-Type: application/json`, тело:

```json
{"code":"<8 символов>","url":"<сохранённый url>"}
```

Ошибки:

- нет `Content-Type: application/json`, тело не JSON или не объект — `415`, `{"error":"unsupported_media_type"}`
- поле `url` отсутствует, не строка, пустое после trim, длиннее 2048 символов до разбора, не абсолютный `http`/`https` URL — `400`, `{"error":"invalid_url"}`

Правило разбора `url`:

1. Обрезать пробелы по краям.
2. Разобрать через стандартный URL-парсер платформы (`new URL`).
3. Если парсер бросает исключение — `invalid_url`.
4. Схема после разбора должна быть `http:` или `https:` (другое, включая `javascript:`, `data:`, `file:`, `ftp:` — `invalid_url`).
5. Хост должен быть непустым.
6. В базу и в ответы пишется `href` результата парсера (канонический вид парсера; path, query и fragment сохраняются).

Каждый успешный `POST /links` создаёт **новый** код, даже если такой `url` уже сокращали.

### `GET /{code}`

Переход по короткому коду.

Успех: `302`, заголовок `Location` равен сохранённому `url`, тело пустое.

Ошибки:

- `code` не существует, либо не ровно 8 символов из алфавита ниже — `404`, `Content-Type: application/json`, `{"error":"not_found"}`, заголовка `Location` нет

`GET /links` (без кода в пути) — это неверный метод на коллекции, `405` / `method_not_allowed`, а не переход.

### `GET /links/{code}`

Просмотр записи без редиректа.

Успех: `200`, `{"code":"<код>","url":"<сохранённый url>"}`.

Ошибка неизвестного или невалидного по формату кода: `404`, `{"error":"not_found"}`.

## Правила короткого кода

- Длина ровно 8 символов
- Алфавит: `A–Z`, `a–z`, `0–9` (62 символа)
- Источник: криптографически стойкая случайность рантайма
- Коллизия при вставке: сгенерировать заново и повторить вставку; наружу ошибка коллизии не отдаётся
- Два разных сокращения никогда не имеют один `code`

## Сохранение

Записи живут в SQLite-файле `data/app.sqlite` и переживают перезапуск процесса. После рестарта ранее созданные коды выполняют `GET /{code}` и `GET /links/{code}` так же, как до рестарта.

## Приёмка

Автотесты должны доказывать все пункты; `bun test` завершается с кодом 0.

1. `POST /links` с валидным `https` URL → `201`, `code` из 8 допустимых символов, `url` в теле равен `Location` последующего `GET /{code}`.
2. Два `POST /links` с одним и тем же URL → два разных `code`.
3. `GET /{code}` → `302` и `Location` на сохранённый url.
4. `GET /links/{code}` → `200` с теми же `code` и `url`.
5. `javascript:alert(1)`, строка без схемы, пустой `url` → `400` / `invalid_url`.
6. Несуществующий код → `404` / `not_found` без `Location`.
7. Неверный метод на `POST /links` (например `GET /links`) → `405` / `method_not_allowed`.
8. Перезапуск процесса: старый код по-прежнему даёт `302`.
9. Тело не JSON → `415` / `unsupported_media_type`.
