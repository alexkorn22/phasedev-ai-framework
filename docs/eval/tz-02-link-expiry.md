## Что добавляется к контракту

Часы для сравнения срока — текущее UTC сервера (`Date.now()`). Ссылка истекла, если `сейчас >= expires_at`. В автотестах срока жизни **нельзя** ждать реальное время: часы в тесте подменяются. Как именно подменять — на усмотрение исполнителя, без вопросов.

### `POST /links`

Как в ТЗ 1, плюс необязательное поле `expires_at`.

Запрос:

```json
{"url":"<строка>","expires_at":"<ISO-8601 UTC>"}
```

или `{"url":"<строка>"}`, или `{"url":"<строка>","expires_at":null}`.

Правила `expires_at`:

- отсутствует или `null` — ссылка бессрочная;
- иначе строка момента в UTC с суффиксом `Z` и полной датой-временем, пример: `2026-12-01T15:00:00Z`;
- дробные секунды допустимы (`2026-12-01T15:00:00.123Z`);
- без `Z`, с офсетом `+03:00`, только дата `2026-12-01`, произвольный текст — невалидно;
- момент уже в прошлом или равен «сейчас» на создании — невалидно (нужен строго будущий момент).

Успех: `201`, тело:

```json
{"code":"<8 символов>","url":"<сохранённый url>","expires_at":"<строка или null>"}
```

`expires_at` в ответе: переданная каноническая строка UTC, либо `null` для бессрочной.

Ошибки сверх ТЗ 1:

- невалидный `expires_at` (включая прошлое и «сейчас») — `400`, `{"error":"invalid_expires_at"}`, запись не создаётся

Прочие поля тела по-прежнему игнорировать. Срок задаётся только при создании: отдельных методов смены, продления и удаления нет, их не добавлять.

### `GET /{code}`

Пока ссылка не истекла — как в ТЗ 1: `302` + `Location`.

После истечения: `410`, `Content-Type: application/json`, `{"error":"expired"}`, заголовка `Location` нет.

Неизвестный или невалидный по формату код — по-прежнему `404` `not_found`, не `410`.

### `GET /links/{code}`

Пока не истекла: `200`,

```json
{"code":"<код>","url":"<url>","expires_at":"<строка или null>"}
```

После истечения: `410`, `{"error":"expired"}`.

Неизвестный код: `404`, `{"error":"not_found"}`.

## Совместимость с ТЗ 1

- Клиент, который шлёт только `{"url":"..."}`, получает бессрочную ссылку (`expires_at: null`).
- Бессрочная ссылка никогда не отвечает `410`.
- Формат `code`, правила `url`, коды `201` / `302` / `400 invalid_url` / `404` / `415` / `405` не меняются.
- Коды, созданные до этой доработки, бессрочные и остаются рабочими.
- Файл базы тот же: `data/app.sqlite`. Если нужна новая колонка или таблица — это внутренняя деталь; публичный контракт не ломать. Старые строки без срока читать как бессрочные.

## Приёмка

Автотесты доказывают все пункты; `bun test` завершается с кодом 0. Все пункты приёмки ТЗ 1 по-прежнему зелёные.

1. `POST /links` без `expires_at` → `201`, `expires_at: null`, `GET /{code}` → `302`.
2. `POST /links` с будущим `expires_at` → в `201` то же значение; до истечения `302` и `200` с этим `expires_at`.
3. После наступления момента тот же код: `410` / `expired`, без `Location`.
4. Несуществующий код: `404`, не `410`.
5. `expires_at` в прошлом, равный сейчас, без `Z`, только дата — `400` / `invalid_expires_at`, запись не создаётся.
6. Два POST с одним URL, у одного есть срок, у другого нет — два разных кода, разное поведение истечения.
